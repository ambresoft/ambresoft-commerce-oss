Sequence is approximate; dependencies and acceptance are set per request. Domain documentation is not authorization to migrate every entity. Do not implement dummy classes, screens, fake data or unused interfaces for later rows.

For each slice inspect current files/rules/decisions, identify invariants and relevant skills, implement only the requested behavior, verify authorization/validation/persistence/UI where applicable and report limitations. PostgreSQL-specific semantics need PostgreSQL tests; frontend interactions need proportionate Vitest/keyboard/visual review. Factories are introduced with real models; seeds only for explicitly required bootstrap/reference data, not cosmetic dashboards.
