# Product stickers

Implemented scope: Marketing administration and backend evaluation. The current request was clarified to **exclude storefront implementation**. The eventual storefront will use **React/Inertia**. This change adds no public product routes, Blade storefront templates, CSS storefront, checkout, or public sticker-media endpoint.

## Administration and ownership

Marketing → Stickers uses the established Inertia/React list, editor, search/filter/sort/pagination, status switch, delete dialog and private image uploader. `stickers.view` protects reads; `stickers.manage` protects definitions, status, deletion, assignments and context display limits. Ordinary permission synchronization registers definitions without changing existing role grants. Product editing additionally requires its normal product capability. Run migrations, `cms:permissions-sync` and `pnpm build`; assign capabilities through Roles as needed.

The sticker editor uses General, Appearance, Display and Product Assignment tabs; Dynamic replaces the last label with Conditions. Tab state uses the existing URL-tab convention and survives save redirects.

The product editor has a Stickers tab for manual assignments and a link to central definitions. It uses the existing bounded searchable target selector, enhanced to search SKU as well as localized product name. Product lists include a correlated assignment count, with no per-product queries. Selectors return 30 search results plus selected records. A definition editor accepts up to 500 products and 12 conditions; a product editor accepts up to 100 manual stickers.

`stickers`, locale-linked `sticker_translations`, typed `sticker_conditions`, `product_stickers` and singleton `sticker_display_settings` are normalized, foreign-keyed PostgreSQL tables. The migration adds explicit type/range/color/schedule checks, indexes and central audit triggers. No existing catalog data is migrated or seeded. The simple CRUD follows the existing Marketing Infrastructure operation pattern; pure product predicates live in Marketing Domain. PostgreSQL advisory lock 2142513 serializes changes with catalog/language edits. Version checks protect both definition edits and shared assignment changes; changing an assignment invalidates the other editor's version.

Soft-deleted/disabled/hidden products retain assignments but cannot qualify. Permanent deletion of either owner cascades assignments. Switching to dynamic removes manual assignments. Cloning products does not copy manual stickers. Trashed products must be removed from a sticker's selected products before saving that definition. Private image bytes follow existing retained-original conventions; media deletion guards cover sticker references.

## Content, appearance and display contract

Every active language requires display text (image alternative text for image styles); short text and tooltips are optional. Inactive language input is rejected. Saved inactive translations are retained. Read fallback selects the requested nonblank text row, then the configured default row; empty optional content is preserved. Internal names never enter the display projection. Six keyed admin dictionaries are registered. Text remains plain and is escaped by the React admin preview; future React consumers must render it as text, without HTML injection.

Appearance supports background, text and border colors, border width, radius, padding, font size, alignment, a restricted class name, and image width. Colors are six-digit hex; pixel values are bounded. Images reuse `ImageAttachment`, `PrivateImageStorage` and `media_files`: JPEG/PNG/WebP, maximum 5 MiB and 6000 × 6000 pixels. Existing sticker images may be reused by media ID. Missing records/files suppress image stickers. Upload rollback compensation and private authorized admin delivery use the existing media infrastructure; no new storage system or public delivery route exists.

Display metadata supports image top/bottom and above/below price, card/detail contexts, and independent mobile/tablet/desktop visibility. Lower numeric priority comes first, then ID. Context limits default to 3 for cards and 5 for details, configurable from 0 through 20. Limits are applied independently per device so a mobile-only label cannot consume a desktop slot. Compact/card output uses short text when supplied; detail output uses full text. The backend returns one entry with a device-visibility map, placement, validated style values, image media identity and intrinsic dimensions. Rendering, responsive breakpoint CSS, accessible tooltip behavior and public media delivery belong to the future React/Inertia storefront.

## Dynamic evaluation

`StickerProducts::forProducts($ids, $locale, $context)` resolves a batch of product identities, current product facts and sticker projections. It currently evaluates the **guest** context: active, complete, undeleted sellable products with active category ancestors and no product/category customer-group restriction. Variation members have their own stock and prices; a sibling's stock never substitutes for the selected identity. The future authenticated-customer storefront must supply an explicit customer context before using group-restricted eligibility.

Manual stickers use only explicit assignments. Dynamic stickers evaluate current data and never persist assignments or change prices, stock, shipping or promotion eligibility. AND/OR is Promotions' existing flat `all`/`any` convention. `PromotionRules` supplies conjunction, inclusive exact numeric ranges and the shared schedule boundary convention. Category targeting shares `CategoryHierarchy` with Promotions. The added `range()` is also used by existing promotion subtotal matching. Cart-specific conditions and benefits are never evaluated as product attributes.

Implemented predicates:

- Selling price, applicable discount percentage and discount amount. These use the existing product-sale chooser, including dates, default guest customer group, priority, quantity breaks and remaining offer quotas. `ProductSales::prices()` batches the same calculation used by the existing single-product/order path. The evaluated quantity is the minimum orderable quantity (minimum quantity, otherwise quantity step, otherwise one). Price is the stored catalog selling amount after applicable product sales, before cart benefits and cart tax adjustments. A list/reference price never manufactures a discount. A discount predicate requires a real positive reduction. Monetary thresholds follow primary-currency precision and convert transactionally with primary-currency changes; percentages and feature values never convert.
- Category identity, optionally including descendants. Product category relationships are authoritative; disabled/deleted references fail closed.
- Existing feature choice identities, numeric ranges and boolean equality. Choice membership, feature status, applicability and type are checked. Localized labels do not participate in equality. Localized free-text feature comparisons are omitted.
- In/out of stock, inclusive quantity ranges and purchasability using existing `AvailabilityRules`/`ProductRules`, ordering limits, inventory tracking, backorder settings and release dates. With tracking off, stock is available but exact-quantity predicates do not match. Exact quantities are never returned in sticker text; no placeholders are implemented.
- Product age: server instant minus creation instant, from zero inclusive to configured days × 86400 exclusive; future-created products do not match.
- Completed sales units using Reporting's existing paid/non-void definition, across currencies (units only). One aggregate is scoped to the batch's products and their orders, and runs only when a sales rule exists. There is no new popularity metric or per-card sales query.
- Product's intrinsic free-shipping flag. This is expressly the product attribute, not a guarantee for every shipping method/destination, and does not infer eligibility from cart promotions.

A dynamic definition requires at least one condition. Unknown types, invalid references and incompatible feature configurations suppress the definition, including OR definitions. Removing a category/feature/option leaves a NULL condition tombstone rather than broadening eligibility. Ratings/review counts are not sticker conditions; product reviews (A98) arrived later and adding such a condition would be a separate change. Active-promotion association is omitted: existing eligibility, stopping and benefits depend on cart context, so there is no safe general product-only decision.

## Scheduling, performance and verification

Enabled definitions may have neither, either or both date boundaries. Admin datetimes use the store timezone and persist in UTC. Start is inclusive; end is exclusive. The server checks current time every evaluation; no scheduler toggles status.

There is no cross-request result/configuration cache and no generated dynamic assignment table. Product, category, feature, stock, sale quota/date, assignment and definition changes are reflected on the next call, with no cache-invalidation backlog. Existing private/no-store HTTP behavior protects admin media. The evaluator batches definitions/translations/media, conditions/references, assignments, features/choices, category ancestors, sale offers/usage and optional paid units. Query count does not increase per product or per sticker. The future listing should invoke the batch service once for the whole page; repeated per-card calls are unsupported usage.

Tests cover CRUD, capabilities/navigation, product editor integration and stale versions, exact price/discount eligibility, category descendants and deleted references, typed features, stock/availability/newness, completed sales cancellation, schedules/timezone/boundaries, translations/default fallback, images/reuse/missing files, style validation, context/device priority limits and constant query growth. React tests cover selectors, conditional fields, language isolation, deletion, view-only access and escaped appearance preview. Public storefront URLs remain absent by regression test. Storefront rendering, SEO/layout/responsive visual checks are deliberately deferred.
